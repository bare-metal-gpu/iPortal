# Security review — 2026-11-04

This review covers the Bun/Effect server, USB transport, native web bridge, runtime files, build dependencies, current source, and reachable local Git history. It is a targeted source review and regression exercise, not a penetration-test certification or proof that unknown vulnerabilities are absent.

## Findings and changes

| Priority    | Finding                                                                                                                                                                                                                                                                                                          | Resolution                                                                                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High        | The main API's browser checks could be bypassed through the separate loopback WDA TCP forwarder. Upstream `FBWebServer.m` permits wildcard CORS; its endpoints do not apply iPortal's Host, Origin, instance, schema, or queue checks. Browser exploitation depends on the browser's local-network restrictions. | USB forwarding now uses per-process Unix sockets inside an atomically created mode-0700 directory. Only the guarded API exposes a Mac TCP listener. Both source and compiled integration suites work while the former forwarding ports are occupied. |
| Medium      | Setup downloaded upstream WDA HEAD, while CI tested one fixed commit. A later clone could silently build different privileged helper code.                                                                                                                                                                       | Setup fetches the exact revision in `scripts/wda-revision`, checks existing checkout identity, and refuses incompatible checkouts without discarding edits. CI verifies the same revision.                                                           |
| Low         | Existing runtime directories could keep broader permissions; a pre-created lease-directory symlink was accepted. New helper logs inherited the process umask.                                                                                                                                                    | Runtime directories are checked without following the final symlink, must belong to the current user, and use mode 0700. Stale leases must be sockets. Helper and Mac session logs use mode 0600.                                                    |
| Hardening   | The native web view had lifecycle/document checks but no explicit navigation-origin allowlist. Framing was not explicitly denied. No working injection exploit was demonstrated.                                                                                                                                 | Navigation and native bridge messages are restricted to the current local mirror document. HTTP responses deny framing, base-URL changes, and form submissions.                                                                                      |
| Maintenance | Package advisories were not checked in CI.                                                                                                                                                                                                                                                                       | CI now runs `bun audit` after the frozen-lockfile install. Runtime and compiler reject Bun below 1.4.4. Compiled binaries expose `--runtime-info` for checking the embedded version.                                                                 |

No UI controls, authentication prompts, device gestures, or permission flows were added.

## Remaining trust boundaries

- **Local native clients are trusted.** The API deliberately has no per-user authentication. Processes that can connect to Mac loopback, including other local OS users, can inspect/control the connected device. The automatic browser instance fingerprint is a browser request guard, not a secret credential. Do not expose the API with a reverse proxy, SSH forwarding, or public tunnel.
- **The phone-side helper remains a developer automation service.** It binds to phone loopback, but still has upstream unauthenticated HTTP/MJPEG behavior. The Unix-socket change removes the Mac-browser bypass; it does not authenticate software on the iPhone itself. Phone-browser loopback reachability and DNS-rebinding behavior were not exercised in this review. A future stricter boundary should use automatic per-run credentials on both helper HTTP and video, with no user-managed secret.
- **The explicit `--wda` development override is operator-trusted.** It bypasses private USB transport and can point to a network helper. Do not use it with an untrusted endpoint. Redirects are rejected for helper and video fetches.
- **The Mac app is not App Sandboxed or notarized.** It launches Xcode tooling and owns USB automation as the logged-in user. Native code, source dependencies, and the local machine remain trusted. This review did not add or validate a hardened-runtime/notarization distribution configuration.
- **Dependency auditing is advisory-based.** `bun audit` checks resolved packages, not the OS, embedded Bun, unpublished vulnerabilities, or every native source file. CI scanning runs on commits/PRs; it is not continuous monitoring between changes.

## Verification

- `bun audit`: no known vulnerabilities reported across 78 packages after updating.
- `bun outdated`: no outdated direct dependencies.
- Gitleaks over all reachable local Git refs: 55 commits scanned, no credential findings. This does not cover GitHub's unreachable commit caches, releases, issue attachments, or credentials that do not match scanner patterns.
- Full `bun run verify`: 64 unit tests plus HTTP/USB, concurrent iPhone/iPad isolation, reconnect/cancellation, guarded input, native validation/rotation, WDA patch compatibility, capture, lifecycle, permission and clipboard tests passed.
- Relocated compiled-runtime suites passed without Node/Bun on PATH, including USB commands/video with the old forwarding ports unavailable.
- Native origin-allowlist tests passed after the final web-view restriction.
- macOS app and iOS status framework builds passed with the new Swift pin; strict deep code-signature verification passed for the Mac bundle.
- Final installed Mac build reports Bun 1.4.4 and opens normally in the disconnected state. The phone was disconnected; this review does not claim a new physical-phone gesture/reconnect test or installation of a rebuilt iOS runner.
